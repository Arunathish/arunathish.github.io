Home Lab Research · 2025

Blue Team · Network Visibility

DNS Filtering & Traffic Visibility

Implemented DNS-level security using Pi-hole and NextDNS to understand how DNS filtering, logging, and policy enforcement improve — and limit — network visibility.

  • Deployed Pi-hole as a local DNS sinkhole to block advertisements, trackers, and malicious domains.
  • Configured NextDNS with custom blocklists, security policies, parental controls, and logging to compare cloud-based DNS filtering with local DNS filtering.
  • Monitored DNS query logs to analyze client activity, outbound connections, and blocked domain requests.
  • Investigated how DNS requests reveal endpoint behavior and communication patterns during normal browsing.
  • Studied the impact of DNS over HTTPS (DoH) and DNS over TLS (DoT) on DNS visibility, and why encrypted DNS can bypass traditional DNS monitoring.
  • Tested different network segmentation scenarios to observe how DNS policies and traffic visibility change across isolated networks.
  • Compared the capabilities and limitations of Pi-hole and NextDNS in deployment, management, logging, and security features.
Pi-holeNextDNSDNS Logging & Analysis DoH / DoTNetwork MonitoringNetwork Segmentation Traffic Analysis
Key takeaway — DNS logs are a strong, underused signal for network monitoring and threat detection, but encrypted DNS (DoH/DoT) meaningfully limits that visibility — which is exactly why comparing self-hosted and cloud-based DNS filtering matters for real-world enterprise decisions.
